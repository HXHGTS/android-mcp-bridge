# 权限与 MCP 接口对照（实施门槛）

本表是 Android MCP Bridge 后续功能的验收基线：**每项在 Manifest 中申请或引导用户开启的权限，必须对应明确的 MCP 读/写工具，或从 Manifest/授权流程移除。**不能把“已申请”说成“智能体已能使用”。所有工具需在 `tools/list` 中自描述权限、范围、副作用和系统限制。

## 现有接口

| 能力 | Android 授权 | 当前 MCP 接口 | 状态 |
|---|---|---|---|
| 电池/省电状态 | 无 | `device.battery` | 已有 |
| 位置缓存 | 前台定位权限 | `device.location` | 已有，只读缓存 |
| 活动通知 | 通知读取特殊访问 | `device.notifications` | 已有，最多30条 |
| 前台使用时长 | 使用情况访问特殊访问 | `device.usage` | 已有，1–168小时 |

## 需要补齐的权限→接口

| 权限类别 | 预期只读接口 | 预期写入/动作接口 | 安全要求 |
|---|---|---|---|
| 联系人 | 搜索、按ID读取 | 新建/更新/删除 | 删除与批量修改需设备端确认 |
| 日历 | 事件列表/详情 | 创建/更新/删除事件 | 明确日历ID、时区；删除需确认 |
| 文件/媒体 | URI/目录列举、读取 | 创建/写入/重命名/删除 | SAF/媒体作用域；路径约束；删除需确认 |
| 相机/麦克风 | 设备能力/授权状态 | 拍照、录像、录音 | 必须可见预览/系统确认与前台指示；不后台秘密采集 |
| 通知 | 活动通知列表/详情 | 清除单条通知（系统允许时） | 默认只读；清除需明确确认 |
| 使用情况 | 时间段应用使用统计 | 无 | 限时段、最多条数 |
| 电话/活动/传感器 | 可用状态/读数 | 仅设备明确支持的动作 | 不含自动拨号/发送短信 |
| 蓝牙/附近 Wi-Fi | 扫描结果/已连接设备 | 发起连接/断开 | 用户授权；仅暴露必要设备信息 |
| 屏幕 | 截屏/录屏帧 | 点击/滑动/输入/系统导航 | MediaProjection 每次会话经系统同意；Accessibility 由用户手动启用；录制有常驻提示；危险写入需设备端确认 |
| 特殊设置 | 授权状态 | 打开相应系统设置页 | App 不静默更改系统级访问控制 |

## 网络边界

- 默认只绑定 IPv4 `127.0.0.1` 与 IPv6 `::1`。
- 局域网开关默认关闭；开启需二次确认。由于 RikkaHub 不支持令牌，LAN 开启后同一 LAN 的设备可无认证调用暴露的工具，UI 必须明确警告。
- LAN 监听只应绑定 Wi-Fi 私有 IPv4/IPv6 ULA 地址；不绑定蜂窝网络和全球可路由 IPv6，不提供公网/端口转发功能。
- 拍摄/录屏/屏幕操作在授权和显式会话开关未开启时必须从 MCP 工具执行失败，不可静默降级。

## Release 门槛

- push 到 `main` 只构建 APK artifact，不创建 Release。
- GitHub Release 只能经 `workflow_dispatch` 手动触发；填写 `release_tag` 才会发布，并附 APK 与 SHA256。
- 正式/预发布前需完成权限矩阵、`tools/list`、读写操作确认、IPv4/IPv6 loopback/LAN 防火墙范围、Android 16/17 安装与权限测试。
